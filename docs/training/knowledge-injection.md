# 直流站文档知识注入：下一轮训练方案

2026-10-08。目标是让模型掌握指定文档中的业务知识，面对直流站运行问题保留条件、诊断分支、操作先后、禁止事项及恢复要求。建议以**闭卷QA监督微调为基线、Prompt Distillation为重点对照**，并分别验证带文档回答能力。方法比较得到正收益后，再扩覆盖和模型规模。

当前按用户要求，优先执行[QA生成质量控制](../qa/quality-control.md)，暂停推进新训练。下文训练与蒸馏是后续实验方案，不以未完成语义复核的候选自动启动。

本文包含方法比较建议。2026-10-08已启动1.7B闭卷SFT先导流水线，实际范围与状态见[远程运行记录](pilot-1.7b.md)；Prompt Distillation、成组自然问法扩展与最终评测仍未执行。原始文档是否正确、现行有效与模型能否忠实掌握文档，是两个不同问题。

## 现状与需要纠正的实验解释

最新语料有1,997条候选，含1,542条操作票、50条按证据组织的自然问答；455条诊断/处置子集有427个chain_id。大部分样本仍是完整原文型问答，数量不能直接代表不同知识、条件分支和自然问法的覆盖。

455条子集的完整训练消息按字符统计：direct中位数426、最大10,690；context中位数2,676、最大34,907。这些不是token数，不能拿它们直接设置训练窗口。全量上下文最大46,340字符。

之前正式训练入口默认读取`sft_context.jsonl`，开发评测也提供来源。因此既有回归主要评估带文档回答；它不能证明闭卷知识注入失败，也不能确定退化只由某一数据、模型或优化器因素造成。旧39题已经参与数据设计，继续作为开发回归，不作为最终未见测试。

硬件记录是远端RTX 4090 24GB。Qwen3-8B曾在19,632-token完整长上下文反向试跑时OOM；Qwen3-4B在同样完整样本的一次前向、反向和优化器步骤通过。这是旧样本的可行性证据，不是新语料或蒸馏已通过的证明。

## 文献支持与项目选择

| 研究 | 对这轮训练的启示 | 本项目的取舍 |
|---|---|---|
| [GraphGen](https://arxiv.org/abs/2505.20416) | 规划知识覆盖、按关系生成不同层次QA，并测闭卷回答 | 用完整链路与分支规划训练预算；不把简单共现当作允许的操作 |
| [Prompt Distillation](https://arxiv.org/abs/2412.14964) | 教师看文档、学生不看文档，匹配回答位置的完整词表分布 | 作为核心知识注入对照，先与普通direct SFT在同一数据上比较 |
| [Deep Context Distillation](https://arxiv.org/abs/2503.08727) | 文档级LoRA知识模块，匹配logits与中间hidden states，可结合RAG | 后续验证版本/设备模块化；首轮先验证logits蒸馏，减少同时改变的因素 |
| [RAFT](https://arxiv.org/abs/2403.10131) | 在相关和干扰资料中学习依据证据回答 | 为最终文档作答能力提供后续对照；不能替代闭卷评测 |
| [AdaptLLM](https://arxiv.org/abs/2309.09530)、[Synthetic Mixed Training](https://arxiv.org/abs/2603.23562) | 阅读理解练习及QA/文档表示混合可帮助领域适应 | 若QA覆盖与泛化出现平台期，再比较原文/结构化文本混合；不是首轮唯一训练目标 |

上述研究支持开展实验，不保证结果能直接迁移到中文直流站长流程。Prompt Distillation部分主实验使用LoRA rank 512/1024和较大计算资源；小rank LoRA或QLoRA是本项目资源条件下的改动，必须标明。论文高温生成可能含轻微噪声的做法，也不直接照搬为允许业务事实出错。

## 第一步：先做链路成组的自然训练数据

优先从455条诊断/处置子集中选20—30个代表性业务链路：控制系统切换、保护检修恢复、阀冷异常、站用电/UPS、线路保护、直流滤波器等。每个链路计划8—12问，总量约200—350条作为首轮方法比较。这是项目预算起点，不是论文证明的最优数量；50条现有自然问答是种子，不机械复制以凑数。

每组包含基本规则、完整处置、明确条件分支、错误前提、恢复和必要的跨册限制。保留一条完整链路答案，同时让聚焦题完整回答所问范围；不把每个问题都扩成整册复述。可以训练承接同一设备/状态的短多轮对话，但不能虚构实际事件、根因或处置成功记录。

示例：同一控制系统故障链路可覆盖“A严重故障、B备用健康”“B未处于备用”“主机重启不成功”“修复后恢复前检查”“能否强行切换”。这些条件只有在来源明确支持时才生成。

学生输入必须能独立表达现场条件。去掉原文时保留设备、站点/版本范围、当前运行/备用状态和题目所需观察信息；多轮保留必要历史。完整来源一直保留在数据元信息、教师输入和审核资料中。

按业务链路控制采样，避免原文完整题、自然改写和同一设备编号的重复票任务反复加权。表格出口、准确数值、版本范围、禁止项和恢复条件分别核查。427个空白值任务、95个模板任务和疑似歧义条款，不转成确定处置标签。

**闭卷训练中不能把“未给原文”一律标成拒答。** 已学且适用条件明确的规则应回答；拒答/澄清针对缺少现场关键条件、版本适用不明、来源矛盾或资料确实未定义的结论。

## 第二步：冻结评测，再比较训练方法

先从独立问题规划中冻结测试问题及来源检查表，生成器不接触测试问题。各方法使用相同知识范围、训练问题和版本；首轮尽量共用已核对的答案序列，以比较训练目标。另记优化器更新量、有效回答token、文档输入token、算力和时间，不把“相同QA条数”当作相同训练成本。

| 运行 | 训练输入与目标 | 要验证的假设 |
|---|---|---|
| M0 基座 | 不训练 | 现有模型的闭卷和带文档能力 |
| M1 direct SFT | 问题→答案；只对回答及结束符计算交叉熵 | 普通QA训练能否注入知识并泛化到未见问法 |
| M2 context SFT | 完整证据＋问题→答案 | 带文档训练是否改善资料理解、分支和完整作答 |
| M3 Prompt Distillation | 教师看完整证据＋问题；学生只看问题，按回答历史对齐分布 | 比硬答案SFT更有效地保留知识与边界 |

M1、M2、M3从同一基座新建独立adapter。首轮不从旧adapter继续累计，否则新数据和旧训练效应无法区分。每个模型都测闭卷、完整证据和检索证据三种推理方式；完整证据模式用于区分检索漏证据与回答模型错误。

先做一轮探索；确定候选方法后用多个随机种子复测。学习曲线按预定checkpoint比较，不因为loss继续下降就一直训练。

## Prompt Distillation的具体训练信号

对同一问题q、完整证据c、核对过的答案a，在每个回答位置i比较：

```text
教师：P_base(token | c, q, a之前的token)
学生：P_base+LoRA(token | q, a之前的token)
目标：在回答位置最小化 KL(P_teacher || P_student)
```

教师参数冻结，无梯度；学生更新LoRA。同规模自蒸馏可以使用同一网络，关闭adapter执行教师前向，开启adapter执行学生前向，分别管理缓存和模式；不必长期同时驻留两份独立模型。如果使用4B教师和1.7B学生，两者不能共享同一网络，应测同时驻留或分阶段计算的显存与存储。但长文档教师前向、词表logits和梯度始终要实测峰值显存，不能仅凭权重共享就保证24GB可行。

GLM可继续用于问题、答案和来源辅助检查。当前接口调用只保存了回答文本，没有完整词表logits；拿这些回答做SFT属于硬目标训练，不是论文中的完整分布Prompt Distillation。首轮用本地开源Qwen取得教师分布。

必须先验证教师拿到完整来源能正确保留关键前提和分支；教师本身不能完成的题，不能靠蒸馏自动变成正确知识。可先比较1.7B自蒸馏和4B教师方案，4B仍不足时再比较已有8B。1.7B与4B的tokenizer、token ID映射和聊天模板已经通过镜像下载及SHA-256核对一致，允许直接对齐输出分布；隐藏层维度与层数不同，不能直接做未定义的逐层hidden-state匹配。

先只蒸馏回答位置的logits；蒸馏温度作为开发超参数，例如比较T=2和4。不要完整缓存“答案长度×全词表”的大矩阵而不估算存储。需要时可做分块计算；若改用top-k分布近似，单独标明近似方式和质量变化。加入hidden-state损失属于后续DCD实验，不与第一轮logits对照一起引入。

## 第三步：模型与资源配置

按用户希望更小基座的方向，首轮改用**Qwen3-1.7B官方后训练版本**，固定revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`。4B保留为效果对照及待验证教师；0.6B可后续测极小模型的能力边界，不作为当前完整流程的默认学生。新测试集仍须重新跑各规模M0，既有4B成绩不能直接代替1.7B基线。

闭卷学生不接收大段原文，训练序列通常明显缩短，因此8B过去在19.6K长序列上的OOM不代表它不能做这轮闭卷训练。所有模型选择仍以新语料token统计和真实最长完整样本试跑为准；不靠删掉前提、截断长答案适配显存。

1.7B优先试BF16 LoRA，避免必须四位量化；若实际完整样本峰值显存超限，再建立明确记录的QLoRA配置。LoRA r=32/alpha=64，非思考模板，仅回答loss，batch=1、梯度累积、高效注意力和gradient checkpointing。SFT学习率先在1e-5至3e-5的小范围开发比较；先观察0.25、0.5、1个数据遍历的checkpoint，再决定是否增加轮数。上述参数是待验证候选，不是已确定最佳配置；rank、温度、训练量应逐项对照。

通用能力保持也纳入固定小型回归集。若需要，加入少量通用指令回放或论文的基座分布保持正则；采样比例按有效回答token记录，并在各方法间控制，不用海量通用样本淹没业务训练。

权重访问继续使用`HF_ENDPOINT=https://hf-mirror.com`，固定模型revision、依赖、tokenizer、模板、解码条件、数据摘要和随机种子。远程执行使用`192.168.30.134`，`x399.njuics.cn`作为备用地址；训练与评测由服务器独立后台作业执行，保存模型、优化器、调度器和随机状态检查点，本机关机不影响作业。

已启动的先导实验采用现有诊断/处置候选415条，而非上文尚待构建的200—350条成组多问法对照集。实际完整训练token中位数349、最长7177，完整最长序列和最长答案试跑均通过，峰值分配5873.4 MiB。配置冻结为BF16 LoRA r=32/alpha=64、LR=2e-5、单轮52更新。32题链路留出开发对照和8题训练题拟合分开报告，微调前后各测闭卷与完整证据。它用于建立direct SFT参照，不直接证明新问法泛化或蒸馏收益。

## 第四步：评测必须回答不同问题

| 评测 | 来源允许怎样参与训练 | 测试输入与意义 |
|---|---|---|
| 已学知识的闭卷掌握 | 允许学到该文档知识；测试问题和近重复问题留出 | 无原文，测新问法、已知条件的新组合及完整处置 |
| 已学知识的带文档回答 | 同上 | 完整来源或真实检索，测是否正确利用证据、避免遗漏 |
| 未见资料/业务单元的开卷泛化 | 测试专属来源和派生QA、依赖证据不进入训练 | 提供测试资料，测新内容理解；若声称未见文档，必须整文档隔离 |
| 条件和版本边界 | 按明确的适用范围设计，不用缺原文自动判拒答 | 缺关键现场条件、冲突条款、新版本、未记载根因和错误前提 |
| 通用能力保持 | 固定独立通用回归 | 测指令遵循和普通问答是否退化 |

闭卷注入允许训练和测试共享同一知识，这是实验目标；隔离的是测试问题与近重复派生题。未见文档阅读则隔离来源本身。这两个目标不能用同一种划分规则混为一谈。

主指标为问题所需的前提/分支/恢复覆盖、数字和设备映射、步骤顺序、禁止项违背、无依据新增事实，以及**完整链路通过率**。答案长短、ROUGE和训练loss只作为辅助。模型辅助评分保留证据和分歧，不能当作业务专家认证。

若direct/蒸馏的闭卷指标提高，但带文档关键条款遵循退化，应检查训练分布与回答方式，再考虑与context样本混合；初期不预设50/50比例。如果没有闭卷收益，先区分教师能力、知识覆盖、adapter容量和优化问题，再决定扩大模型或训练数据。

## 扩展顺序与产品部署

方法比较有效后，再按覆盖缺口扩到约1,500—3,000条有不同任务的自然QA，增加多轮承接与跨册链路；这个规模同样是预算建议。批量操作票按实际覆盖需要抽样，不把所有设备编号当作独立诊断能力。

后续若需要不同设备/版本独立更新，可借鉴DCD和[Parametric RAG](https://arxiv.org/abs/2501.15915)构建控制保护、阀冷、站用电等知识模块。模块要带版本与依赖；跨模块流程仍要联合验证，不能假设删除一个adapter就删除了其他模块里重复的知识。

最终应用可让参数掌握稳定业务概念和诊断结构，检索补充现行版本、精确定值、接线和具体操作票，并验证提供的证据能约束回答。闭卷知识注入实验继续独立保留，不因产品采用检索而取消。

暂不把DPO/RLVR作为主实验：当前缺少可靠的完整流程偏好或奖励标注。K2V式可验证训练可以先在明确数值/出口映射小范围尝试，不能直接代替全流程监督。

先完成代表性链路的成组QA、冻结分开的评测集、跑M0和教师资格检查，再实施M1/M2/M3。任何训练方法都不能把未核实的来源条款自动变成已认证的现场事实。
