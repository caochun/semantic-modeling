# 姑苏阀冷事件窗口候选集：首批交付

2026-10-09。

已完成 [24个窗口的逐条复核包](../../data/decision/gusu-valve-windows-v1-candidates/README.md)。范围是姑苏站极2低端VSC1阀冷的 `P221VCC1/P221VCC2`，A/B通道全部保留；覆盖7个实际事件日、4,855条事件、72项候选决策。

本次目标是形成可核对的数据集。没有继续训练：当前缺少有足够证据的“符合预期”样本，部分窗口过长，现场/试验背景也尚未逐窗确认。这些是实际数据条件，不是新增的用户授权要求。

## 1. 已完成的工作

- 解析姑苏站第一阶段29份事件导出，按正文时间归档，严格解析目标主机记录。每条保留原始内容、等级、设备、通道、时间、源文件SHA256、行号及原始行。
- 人工选择24个覆盖风机、屏蔽、故障、恢复和上下文不足的窗口。保留窗口内两个目标主机的全部事件，并加入此前5分钟上下文；没有只挑有利于标签的事件。
- 将运行规程一、三、五的相关内容绑定到候选判断；另核读两份姑苏调试日报中的高端阀冷试验，明确它们不能直接解释本批低端事件。
- 建立窗口内异常证据、窗口末异常证据、已见目标信号是否复归三个问题，保留标签依据和业务复核空位。
- 按实际事件日冻结建议分组：13个训练候选、4个校准候选、7个测试候选。两个主机、A/B、相邻窗口及变体同日同组，分别来自3/2/2个事件日。规则在集合间重用，不宣称规则族隔离或未见规则泛化。
- 为7个测试窗口各生成3种候选语义换位请求，共21条。它们仍然只有7个窗口、2个事件日，不是21个独立案例。
- 用户提供的2026-09-11日志继续保留为外部评测案例；构建程序不读取其日志或标签，原试点数据和权重不变。

文件名存在明确日期差异：`saveevent0607`几份正文是2022-06-08；`saveevent0613 00-05/05-08/08-10`正文是2022-06-14。本批依据正文时间建组，文件名原样保留。

## 2. 标签含义及分布

“有异常证据”指有明确异常信号/现象，**不等于已经证实设备损坏**。调试注入也可能产生这些信号。窗口末“有异常证据”只表示已观察到出现且未见后续复归的最后已知记录；没有采集完整性证明，不能将其解释成确定连续存在的现场故障。

| 问题 | 候选分布 |
| --- | --- |
| 窗口内异常证据 | 有异常证据13；信息不足11；已核实符合预期0 |
| 窗口末异常证据 | 未见复归的异常证据9；信息不足15；已核实符合预期0 |
| 已见目标信号复归 | 均复归4；部分未复归7；均未见复归2；未观察到目标信号出现11 |

候选由明确的信号匹配和逐通道状态追踪生成；不是模型投票，也不是专家金标。匹配表、规则引用、未覆盖的非“正常”等级事件均随样本保留。源码中的词表是待复核的信号语义假设，规程的故障类别条款并不等同于逐点信号字典。

没有通过以下方式制造正常样本：没有故障关键词、事件等级写“正常”、屏蔽消失、部分故障复归。当前规程数值定值也没有被直接用于反推2022年历史事件，软件版本适用性未知。

建议先看 [2022-06-06 11:00–11:16案例](../../data/decision/gusu-valve-windows-v1-candidates/review/gusu-valve-20220606-1100.md)：

- 26条完整范围内事件，出现风机变频器故障、冗余冷却能力丢失，随后A/B均复归。
- 窗口内候选：有异常证据。
- 目标故障/冗余信号复归候选：均复归。
- 系统末端候选：信息不足。记录中还出现液位高等状态，且没有完整末端状态确认，不能从已见目标信号复归推出整个阀冷系统正常。

## 3. 长度与信息保留

原文重复大量主机、设备和信号名称。模型输入使用可逆字典：设备表、消息原文表，以及逐事件的相对毫秒时间、设备/消息索引、原始等级和时间标记。前置上下文用负时间表达。每条编码均已逐字段反解比对，原始行仍保存在数据及Markdown中。这里没有让模型摘要或删除不相关事件。

在.134服务器上仅使用CPU、固定模型tokenizer和官方 `encode_record` 测量完整输入，未加载模型权重：

| 长度条件 | 窗口数 |
| --- | --- |
| 不超过当前训练4096 token | 11（训练7、校准2、测试2） |
| 超过4096，但不超过16384 | 11 |
| 超过当前推理16384 | 2 |

完整输入范围为1683–21830 token。两个最长窗口是2022-06-08 15:00（21830）和2022-06-12 15:00（18366）。上述26条示例是1842 token。

[实际长度报告](../../experiments/decision_model/results/gusu-valve-windows-v1-lengths.json)绑定候选输入文件哈希。本次没有截断，也没有为了让数据可训练而把长窗口直接排除或随机切开。

下一版处理长窗口时，应由业务事件边界决定拆分，并携带前段最后已知状态及证据。所有子窗口沿用父事件日分组。跨窗口屏蔽和故障恢复不能因为切分而变成“首次出现”“超时”或“恢复”；不能将截止时间之后的信息写入当前判断。

## 4. 文档核查仍缺什么

已检索现有姑苏目录174份非临时文件的可提取文本/文件名，并重点核读规程和有关日报；检索范围和表达式保存在 [来源缺口检索记录](../../experiments/decision_model/results/gusu-valve-window-source-gap-search.json)。该检索不覆盖全部图片/图纸OCR，也不是对全部语义等价措辞的穷举。

| 缺口 | 本次发现和处理 |
| --- | --- |
| 风机启停触发屏蔽、重触发计时及解除条件 | 未找到可用于本设备的明确约600秒条款。保存时差观察，不据此编造规则。 |
| 日志“许继”名称与晶锐设备、两个主机及A/B点名映射 | 规程支持设备配置和冗余结构，逐点映射仍需点表；不合并通道状态。 |
| 数字告警等级 | 历史导出为文字等级，不能用来证明用户日志数字3的映射。 |
| 正常调节/操作的闭环依据 | 未找到与这些低端窗口直接对应的完整操作和运行确认；不能拿高端试验成功作为低端正常标签。 |
| 实际故障还是试验注入 | 数据位于调试归档，部分日报有明确注入操作，但本批低端窗口尚未建立对应关系。 |
| 初始/末端状态及采集完整性 | 已保留导出文件中范围内全部记录，不能证明现场采集从未丢失，也没有全量状态快照。 |

正常/符合预期样本补齐前，不适合用当前三分类分布继续训练并宣称能够区分正常与异常。当前产物适合逐窗核读、补充点表和操作背景，以及设计完整事件窗口的输入方式。

## 5. 下一轮训练的验收方式

完成标签和长度问题后，使用冻结的事件日分组，比较当前模型与新的阀冷专项模型；候选标签未经业务确认时，只报告与候选的一致性，不称现场准确率。

- 分别报告窗口内、末端、恢复三个任务及事件日数量；不以选项排列次数扩充样本量。
- 三分类任务检查三个语义与选项键循环换位后的结论一致性；恢复任务有五类，当前三次轮换不是全部排列覆盖，正式验证应另补其五个位置。
- 对同一父事件制作明确标记的观测缺失对照，移除故障证据后重新核对标签；不能继承原标签或将删减版冒充完整历史窗口。
- 检查加入明确故障、补入复归、移除操作背景是否产生预期变化，避免固定选择异常或证据不足也能通过。
- 分别核查异常漏报、将缺失信息误报为正常、将已复归误报为未复归；置信度单独评估，不以高confidence替代正确性。
