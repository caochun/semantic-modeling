# 规程五中的明确决策 State 筛选与数据构建

规程五并非每一段都适合直接训练 Decision Model。大量条款只是“检查某项设备”或“联系检修”，尚未给出可由 State 选择的互斥分支。本批只选择满足以下条件的条款：

1. 有明确的触发现象；
2. 有明确的核查变量或结果；
3. 条款对不同结果给出不同分支；
4. 分支可以由任务级 State 表达；
5. State 缺少关键核查结果时，可以明确标为“需要继续核查”，不把未知当成任一分支。

## 首批选择

| 规程 | 可判定 State 条件 | 决策分支 | 条款 |
|---|---|---|---|
| 14.1 阀厅空调室外机故障 | 复归后报警消失 / 仍存在 | 加强监视 / 切换备用机组并通知检修 | 14.1.2.1–14.1.2.3 |
| 14.2 压差传感器报警 | 传感器异常 / 传感器正常且读数超过设定值 | 检修 / 切换机组并更换过滤网 | 14.2.2.1–14.2.2.3 |
| 13.4 泵房漏水 | 发现明显管网破损漏水 / 未发现明显漏点 | 隔离漏点并检修 / 进一步检查分析 | 13.4.2.1–13.4.2.3 |
| 13.5 生活泵故障 | 另一台自动正常 / 不能自动 / 两台均故障 | 安措检修 / 手动启动并储水 / 检修 | 13.5.2.1–13.5.2.5 |
| 15.12.6 消防水池缺水 | 实际液位低属实 / 现场正常且信号不一致 | 补水并查自动补水原因 / 记录传感器故障 | 15.12.6.2.1–15.12.6.2.3 |
| 15.13.1 火灾自动报警误动作 | 有火情 / 无火情且复位不再报警 / 无火情但重复报警 | 火灾预案 / 误报警巡视 / 屏蔽回路并维修 | 15.13.1.2.1–15.13.1.2.3 |
| 10.5 主循环泵异常未切备用 | 控制方式、主泵现场状态、备用泵投入结果 | 自动位置核对 / 主泵切换 / 申请换流阀停运 | 10.5.2.2–10.5.2.5 |

这些条款适合作为第一批数据构建对象，因为分支条件直接来自现场核查结果。`14.2` 中“传感器正常但读数不超过设定值”没有对应处置句，因此数据中保留 `needs_measurement`，而不虚构“正常”或其他操作。

## 数据分层

每条样本分成两层：

```text
原始/合成观测事件 → 任务级自然语言 State → 规程分支标签
```

模型输入只包含自然语言 State 和一个分支问题。原始事件、结构化核查结果、条款定位、状态构建器版本和标签理由写入 `audit.jsonl`，不进入模型输入。这使 State Builder 和 Decision Model 可以分别评测。

首批构建入口：

```sh
python3 -m experiments.decision_model.explicit_state_dataset build \
  --output data/decision/gusu-explicit-state-v1
python3 -m experiments.decision_model.explicit_state_dataset verify \
  --output data/decision/gusu-explicit-state-v1
```

当前数据是规程派生的合成种子集，已核对 Markdown 条款和来源哈希，但未经运行人员或领域专家确认。它用于验证“明确 State → 明确分支”的训练和评测链路，不能作为现场故障率、自动操作依据或规程正确性的证明。
