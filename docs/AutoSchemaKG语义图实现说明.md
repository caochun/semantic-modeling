# AutoSchemaKG 方法在本项目中的适配

本项目参考 AutoSchemaKG 的实体—事件—概念表示，但把语料驱动的离线全库构图改成问题驱动的在线局部建模。

## 对应关系

论文中的知识图为：

```text
G = (V, E, C, φ, ψ)
```

在本项目中对应为：

| 论文对象 | 任务模型对象 | 说明 |
|---|---|---|
| 实体节点 | `Node(kind="entity")` | 设备、系统、站点或其他业务对象 |
| 事件节点 | `Node(kind="event")` | 切换、告警、跳闸、状态变化等事件 |
| 概念集合 `C` | `Node(kind="concept")` | 当前问题需要的抽象类别 |
| 关系边 `E` | `Fact.atom` 及 `graph.edges` | 关系、上下文、否定状态和原文证据 |
| 节点概念化 `φ` | `ConceptLink(role="node")` | 实体/事件到概念的映射 |
| 关系概念化 `ψ` | `ConceptLink(role="relation")` | 事实边到关系概念的映射 |

事实边会根据端点类型标为 `entity_entity`、`entity_event`、`event_entity` 或 `event_event`。没有充分依据的边仍可以显示为候选，但不能进入确定性推理。

## 与论文流程的差异

论文先对整个语料库分阶段抽取实体—实体、实体—事件和事件—事件三类关系，再对图元素进行批量概念化。本项目保留这三个抽取目标，但由当前问题和开放缺口决定抽取范围：

```text
问题
  → 任务目标和查询映射
  → 当前缺口
  → 定向证据
  → 关系抽取
  → 节点/关系概念化
  → 局部图合并
  → 路径和规则推理
```

论文的概念化结果用于大规模图的组织和检索。本项目还要求概念映射保留证据，并明确概念边不能自动推出实例事实，防止把“同属某概念”误当成异常或因果结论。

## 两种推理保持分离

任务模型同时保存两种结构：

1. **语义图路径**：在同一上下文中沿支持的有向事实边进行有限深度搜索，记录起点、终点、每条关系、证据片段和搜索前沿。路径只表明关系链存在。
2. **规则证明路径**：用复核通过的事实和条件规则执行 Horn 风格闭包，记录事实证明、规则、绑定变量、前提步骤和原文出处。只有这类规则证明可以支持“满足条件”“违反约束”等可计算结论。

图路径验证会重新执行同一查询，检查方向、谓词顺序、上下文、终点、边状态和证据；规则证明验证会在模型快照上重放全部绑定和 guards。模型版本或指纹发生变化时，旧推理报告自动失效。

## 换流站监盘示例

针对“收到直流站日志后，如何判断各系统是否存在异常”，一个局部模型可以包含：

```text
控制系统 --参与--> 系统切换事件
系统切换事件 --目标--> 目标系统
目标系统 --具有状态--> STANDBY
告警事件 --发生于--> 控制系统
告警事件 --先于--> 通信中断事件
```

规程可以形成规则：

```text
发生系统切换
且目标系统实际状态不是 STANDBY
→ 切换目标状态异常
```

如果规程只说明必要状态，而日志没有提供目标系统的实际状态，模型会把它登记为数据缺口。图路径可以帮助定位“切换—目标—状态”的证据链，但不会在缺少日志事实时生成异常结论。

## 保存边界

任务模型每次更新都会保存完整快照；只有证据摘录匹配、结构检查通过且独立复核为 `supported` 的事实、规则和概念映射才可进入推理。候选元素可在界面查看，但不自动作为推理前提。跨问题复用仍需重新检查来源版本、适用范围和当前任务缺口。

目前不声称实现论文中的网页规模构图、全局概念统一或复杂时序/空间推理。后续评估应分别测量关系抽取准确率、概念映射质量、路径证据完整性、规则结论准确率，以及去掉图和路径后的消融结果。
