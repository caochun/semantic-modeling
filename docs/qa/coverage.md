# QA 覆盖边界与业务信息盘点

不能靠 QA 数量、模型审核通过率或“再也生成不出新题”证明全部有价值业务信息已覆盖。覆盖的分母必须先从来源独立建立，未解析和未审阅内容必须保留。当前还没有建立全库业务事实分母，因此不报告全库覆盖率。

## 边界怎样确定

项目目标是支持直流站运行中的问题识别、诊断、处置和恢复。这个目标决定哪些信息需要盘点；现有文档、站点、设备和版本决定哪些答案能有证据。当前规程题限定姑苏站和所列版本，不把历史案例、其他站点或厂家说明自动提升为本站现行操作规定。

“任何运行问题”可以作为长期服务目标，但现有材料不能为尚未记载的故障、现场实时状态或未来配置提供确定方案。合成 QA 只能构造文档支持的条件情景，不能冒充真实事件、测量记录或已验证处置结果。文档没给出关键判据或动作时，保留资料缺口，并检查相邻章节和其他来源。

业务价值判断遵循明确标准，而不是让生成模型挑它容易出题的段落：

| 信息类型 | 为什么必须纳入 |
|---|---|
| 告警、现象、诊断判据和区分故障的条件 | 决定问题识别与下一步检查 |
| 适用设备、运行状态、模式、版本、例外 | 决定能否套用方案 |
| 动作对象、步骤、时限、次数、先后和可并行关系 | 决定实际处理路径 |
| 申请、确认、指挥职责与禁止操作 | 决定权限和约束 |
| 成功/失败分支、恢复检查、保护复归 | 决定链路能否完整结束 |
| 保护后果、设备映射、拓扑、参数和限值 | 支持故障判断和行动选择 |
| 历史案例及厂家说明 | 提供限定范围的机理和经验，不能直接替代规程 |

封面审批名单、纯目录等元信息可以不出业务题，但保留其位置与排除理由。含参数和拓扑的前言仍是业务候选。重复内容可合并知识点，条件、站点、版本不同的内容不能随意合并。有争议的信息保持“待判断”，不能因为不易出题或难解析而删除。

## 怎样判断有没有漏

先独立遍历来源目录、正文、附录、表格、图和引用；再把每个有意义的来源单元拆成事实与关系。一个条款可能包含多个命题，例如“备用泵正常、故障泵隔离检查期间，禁止相关站用电切换”至少包含运行状态、时间范围、设备对象与禁令，不能只提取“禁止切换”。有动作清单的表格要恢复行列、合并单元格和表头关系，单个数值不能当作完整知识点。

事实清单包括诊断、适用前提、公共动作、条件分支、权限、禁止项、结果和恢复要求。关系清单包括“先于”“仅在……时”“除非”“由谁批准”“与哪条规则共同适用”。它们在生成 QA 前建立；之后逐项寻找已复核 QA 的支持，反向从原文查漏。

分别检查以下层面，不混成一个数字：

1. **来源完整性**：原文件是否全部纳入，目录与正文是否对应，图表是否解释，跨页文本是否接续。目录全匹配只说明没有丢标题，不能证明图表或语义完整。
2. **事实覆盖**：每个业务命题是否在已复核 QA 中正确表达，条件、对象、数字和确定性是否保留。整个章节出现在上下文里不算覆盖；短引文触及复合条款也不算整条覆盖。
3. **关系与分支覆盖**：各适用条件及成功/失败路径是否可区分，禁令、权限和顺序是否保留。不能用只适用一个分支的题代表整个预案。
4. **完整链路覆盖**：是否有题从识别走到处置和恢复，并保留相关公共规则与跨册限制。聚焦题不必复述全部步骤，但其答案不能与完整链路矛盾。
5. **模型能力验证**：训练后，用未见问法、信息缺失、相似故障和多轮追问检查是否会用这些知识。这是另一个问题：语料已覆盖不等于模型已学会。

事实分母充分审定后才能计算“已完整覆盖事实数/全部纳入事实数”；分支、关系和完整链路另算。高风险信息可以优先和加权，但必须同时显示未加权缺口，不能用大量简单背景题冲淡关键遗漏。

有限知识可以被多种问法反复表达，问题措辞则没有可穷尽的上限。因此停止条件是“约定来源范围内的业务事实与关系逐项有去向、关键链路可闭合、未知项有清单”，不是生成固定数量的 QA，也不是穷举所有可能问题。没有业务专家时，AI 对业务价值和来源本身的判断仍可能漏项；独立盘点、原文逆向审计和异议记录用于降低遗漏，不能证明绝对完备。

## 本次实际完成与仍存在的缺口

[覆盖台账](../../.semantic/qa_coverage_20261008_batch04/README.md)登记 174 份去重业务文档，已有完整或部分提取产物 17 份。目前先独立盘点第五分册和第三分册，没有使用旧 QA 或旧 coverage_units 构造分母。

第五分册得到 1,913 个来源片段，其中 1,903 个编号片段、前言 1 个、目录/封面 9 个；194 个目录条目均找到正文编号。第三分册保留全部 17,419 个原始正文块，包括前置元信息；106 个编号章节/附录目录项均找到正文标题。旧 Word 中的 13,785 个正文表格线性化单元格及 2 个带未解释对象的段落仍保留为待解释项。两种粒度不同，不能把条款数和单元格数相加计算业务覆盖率。

目前累计 180 条保留逐题来源复核记录的 QA、27 个业务单元、274 个事实规划条目；后者没有按知识去重，不能当作 274 个独立业务知识点。第三批新增公共原则、应急权限、事故协作、通信中断、备用泵失败及电导率报警共41题；第四批再补线路、母线、开关/GIS状态与保护动作50题。

除逐题忠实性复核外，累计按完整提取文本检查了235个来源单元：第二批26项、第三批42项、第四批81项、第五批86项。已核对的第三分册5.7注记沿用原记录，不重复加1。每条覆盖判定绑定原文和事实摘要，保存条件、权限、顺序、结果和数值检查。另有27个来源单元只是被已复核事实的短引文触及，尚未确认整条全部命题覆盖。三个岗位/指挥条款仍保持部分关联，因为所问职责复核与整条能力要求、总领句及下属义务关系的全面覆盖是不同判定。

这些数字不表示全库覆盖率。大量条款尚未拆解，172 份文档尚未建立独立业务目录；第五分册的图表与稀疏页检查、第三分册的表格关系和自动编号仍未解决。概述的 STANDBY 事实已有 QA 忠实性复核，但概述尚未独立盘点，所以该事实单列在“未建立目录的来源关联”，不把概述整份算作已覆盖。

两册前言也保留为业务候选，因为包含额定参数、接线拓扑和设备改造记录。第三分册和第五分册前言均自称“设备概况分册”，与各自标题不一致，已分别按来源ID及原段落记录疑点，待核实；不会自动据此改正文条款或认证现行性。两册的封面日期本来不同，不能把这个正常差异和各自前言疑点混成同一种版本冲突。

具体缺口包括：

- 主泵10.4正常备用与10.5备用未切入/也故障已分别构建并复核，后续仍需核对不同控制模式、硬件回路故障和检修后复役条件。
- 2.1/2.2公共规则已有独立QA；仍需逐个设备链路确认这些公共规则与专门规定在所问状态下如何共同适用，不能因为公共题存在就自动宣称每条具体方案完整。
- 国调立即/5/15/30分钟的题不能代表同节华东分中心的规则，也不能代表全部调度管辖范围。
- 主泵检修后的复役顺序不能从 10.4 补造，需要另查设备启停、典型操作票及引用条款。
- 附录中的顺控、启停检查、保护后果、联闭锁和功率限值仍需先恢复结构再拆知识。
- 第四批已覆盖线路试送、重合投退配置、母线真实故障/误动及GIS预案；变压器试送禁止句与许可句边界、开关公共/GIS专项同时触发的衔接、检修后复役票仍[未闭合](../../data/qa/batches/20261008/batch04/pending_business_issues.json)，不生成无条件操作方案。

第五批已盘点直流闭锁、保护后果及回降路径，后续优先补规则衔接、降压适用边界和设备恢复缺口；然后扩展保护跳闸表、故障汇编和典型操作票。对于图表或旧 Word 表格，先改善解析、检查跨册关系，再生成确定操作答案。
