# 文档 QA 生成与逐题质量控制

当前优先工作是控制QA质量。暂停推进新微调，不把旧候选的结构检查、复答完成数或模型评分当作训练准入。已完成的模型和实验结果保留，以便后续对照。

## 生成前先确定知识与业务链路

每个业务单元先整理来源版本、设备对象、适用条件、公共步骤、互斥或并行分支、禁止事项、申请权限、恢复条件和未定义内容。事实表在写问题及答案前建立；每项事实关联原文位置，不从候选答案反推“标准检查表”。

保留完整链路，不机械按字数切分。同一链路可生成完整处置题、条件分支题、前提题、错误前提纠正、恢复题、资料缺口题及少量多轮追问。只生成来源支持的条件变化；不要求每条链路凑相同题数，也不添加没有依据的真实事件、测量值或处置结果。

聚焦问题完整回答所问范围，不必复述整份预案；整链路问题则覆盖全部必要阶段。答案按业务条件组织，分支不能变成依次执行的步骤，紧急立即执行的要求不能被其他检查延后。多轮同时保留原始历史、当前问题和补全指代后的独立问题。

## 逐题检查顺序

| 检查 | 执行方式 | 通过要求 |
|---|---|---|
| 原文与解析 | 校验原文件摘要，回查章节、页/段/表格位置；记录无法恢复的图表及编号 | 问题所需证据可读、没有未知的关键结构 |
| 事实表 | 对照原文逐条检查完整事实，而不只检查所引短句 | 对象、条件、数字、权限、确定性与例外都有支持 |
| 问题 | 核对站点、版本、设备、现场状态和历史依赖 | 能确定所问范围，不偷渡不存在的事实；缺信息时明确问澄清或资料缺口 |
| 完整性 | 对照生成前的必要事实、分支和顺序 | 所问阶段没有遗漏，没有把聚焦题扩成不相关流程 |
| 扩展上下文 | 检索并阅读同设备相邻章节、引用条款、其他册及相关限制 | 相关限制不遗漏；无法解决的版本冲突或歧义暂缓 |
| 答案盲复答 | 复答器只看原文与问题/历史，不看候选答案或必答清单 | 保存完整复答，按原文分析遗漏与分歧；不能按回答一致性投票 |
| 问答审阅 | 原文、候选、必答事实与复答一起审核 | 条件、步骤、禁止项、恢复、措辞确定性及新增结论均核对 |
| 来源复核与修订 | Codex逐条对照原文，分析模型意见与未提供给模型的关联资料 | 不机械采纳模型pass；保留修订前后及原因，再审核修改内容 |

关键词命中、引文存在和答案正常结束属于结构证据。它们不能证明事实蕴含、分支正确或流程完整；结构与语义状态分别保存。

## 三种处理结果

- **按所列来源通过忠实性复核**：问题清楚，所问事实有支持，必需条件和步骤完整，无关键权限、数值、禁止项或恢复错误。保留原始证据与审核身份；不等同于来源现行性认证。
- **修订后复核**：问题范围、措辞、条件、事实映射或关联限制可依据原文明确修正。保留旧版本；问题、答案、证据或历史变化后，旧审核不能直接移植。
- **暂缓**：关键图表无法解析、冲突版本未定、原文歧义或关键结论无支持。可以针对已确认的资料缺口生成QA，不能把不确定结论写成确定操作答案。

任何关键检查失败或未确定，不能用其他项的高分抵消。模型审核只能给建议；同一模型用于事实核验、复答和审阅会产生相关错误，不称为三个独立模型认证。没有业务专家的条件下，当前目标是文档忠实性、链路完整性及可审查性，来源自身正确与现行适用状态单独记录。

## 审核记录与数据使用

每题保存完整问题/历史/答案、业务单元ID、必答事实及引用、顺序边、完整上下文、资料缺口、审核提示和真实响应、逐项判定、分歧处理、修订说明及所有输入SHA-256。修改后的候选必须绑定新的审核摘要；完全相同的答案盲提示可以复用旧响应，但要验证提示摘要并记录复用来源。

候选、已复核样本、训练数据分别保存。当前质量小样本不生成SFT导出；复核完成也不自动启动训练。以后重建训练集时，以逐题审核记录为依据，按完整业务单元控制采样；已学知识的新问法评测与未见资料的开卷评测另行设计。

1,997条旧候选先保留为证据与覆盖库存，不能按“旧结构验证通过”自动迁入新训练集。新流程的`legacy_quality_inventory.jsonl`逐条记录其待核验状态，并保留旧审核记录。

## 首批实际执行

三条链路：倒闸异常、控制A单系统严重故障、内水冷泄漏。共18题，每条链路6题；这是验证流程的目的性小批次，不能估计整个语料的正确率，也不是最终测试集。

首轮已经发现并修订：

1. 问题追问具体申请岗位，但引用条款未明确岗位；答案改为声明该条款的资料缺口，不采纳复答器自行指定岗位的推断。
2. 控制系统切换条件跨两份来源，改为分别标明8.2.2.2的操作与《设备概况》的STANDBY前提，不混写成一条原文。
3. 完整倒闸异常链路补充：影响其他设备安全时，还须向受影响设备对应调度汇报。
4. 慢降水位查漏问题补回阀塔漏水时的领导批准与停电分支；完整题强调迅速下降必须立即申请停电，不先等待其他检查。
5. 阅读相邻10.4后，补充故障主泵隔离检查期间的相关站用电切换禁止及单泵运行监视要求，明确适用状态，避免把另一故障预案全套并入。
6. 解锁规则补明“检修人员确认”的主体；解锁程序由现场运行人员履行，不能模糊角色。

首版、第二版和第三版分别保存在`.semantic/qa_quality_20261008`、`_v2`和`_v3`目录，保留全部模型意见。第二版模型全部pass后仍由来源核对发现第5项缺口，证明上下文审计和模型审阅需要分别执行。

最新样本：[离线阅读页](../../data/qa/batches/20261008/batch01/index.html)、[候选JSONL](../../data/qa/batches/20261008/batch01/candidates.jsonl)、[事实与原文](../../data/qa/batches/20261008/batch01/chains.json)、[逐题复核记录](../../data/qa/batches/20261008/batch01/review.md)。

第三版已完成27项事实、18题答案盲复答和问答审阅，随后完成逐题Codex来源核对，记录绑定到实际候选及模型响应摘要。当前状态是小批量文档忠实性复核完成，仍没有训练导出，不估计全量准确率。GLM复答中额外推断申请岗位、故障后果、状态映射以及引用标识笔误均单独记录，未自动吸收到候选答案。

下一步依同一流程按覆盖缺口扩展其他链路，统计修订与暂缓原因，并抽查模型通过和模型拒绝的题；先验证质量控制稳定性，不以凑够训练条数为目标。

## 第二批与独立覆盖盘点

第二批增加黑启动、主泵故障、国调故障汇报3条链路、18题，累计36题逐题文档忠实性复核。新批的26项事实完成GLM核验，18题完成答案盲复答及审阅，随后逐题Codex来源核对。首版把资料边界判断混进本站配置事实，已分开；主泵开关跳开的检查条件不再作为与电机外观正常互斥的同级分支，国调时间线不再使用分支提示。

最终GLM原始审阅含证据ID和必检字段拼写错误，解析后11题pass、7题hold。原始意见完整保留，缺字段赋uncertain、未知引文标记source_support uncertain，未静默修复为pass。Codex另行按实际原文逐项核对并保存绑定记录。模型意见与来源复核有各自身份，不把Codex复核完成写成“全部模型审核通过”。[本批阅读页](../../data/qa/batches/20261008/batch02/index.html)与[审核说明](../../data/qa/batches/20261008/batch02/review.md)可回查。

同时建立[覆盖边界与业务盘点](coverage.md)：来源目录独立于已有QA，保留174份去重文档登记，先遍历第五与第三分册的全部提取文本，再映射已复核事实。宽上下文或短引文命中不会自动获得整条覆盖状态；全条覆盖另有逐项语义记录。未解析的图表、表格结构和未盘点文档保留为缺口，当前不报告全库知识覆盖率。

## 第三批：按来源缺口扩展

新增41题、6个业务单元，累计77题。补齐公共事故原则、应急权限、现场协作、调度通信中断、备用泵失败和电导率报警，加入3道完整历史的多轮题。事实与问题规划直接使用独立原文台账，不依赖旧QA是否存在。[统一阅读入口](../../.semantic/qa_reviewed_20261008_batch03/index.html)、[批次记录](batches.md)与[逐题复核](../../data/qa/batches/20261008/batch03/review.md)可查。

本批修订了问题范围内遗漏的防误操作、是非题未直接回答、备用正常/失败分支表达不够明确，以及孤立正文片段缺少版本和章节证据的问题。最终模型33题pass、4题revise、4题hold；Codex对每题另查原文并处理分歧，记录41题文档忠实性复核完成。未把这写成全部模型pass，也未把模型对语义推断的过度字面判断直接当作业务结论。

复答复用支持逐题完整提示匹配：相同ID但上下文、历史或问题变化时不复用。汇总产物保留原候选和审核的摘要，当前不生成SFT导出。完整性检查新增直接来源偏移、未解释结构、缺必答事实审核及复答提示变化的拒绝路径，累计25项测试。

## 第四批：状态变化与跨条款关系

新增50题、8个业务单元，累计127题、20个业务单元。专项来源涉及线路、母线、GIS和断路器保护，追加3道合成多轮题，要求最新状态改变时切换原处置分支。[当前统一入口](../../.semantic/qa_reviewed_20261008_batch04/index.html)、[逐题复核](../../data/qa/batches/20261008/batch04/review.md)和[整条覆盖台账](../../.semantic/qa_coverage_20261008_batch04/index.html)可查。

补齐国调管辖事故的立即初报与查明后详细汇报，避免把设备条款查因后报告当作延迟首报。加入两册各自封面和日期，检查source_id对应文件，不能因为第三、第五分册日期不同就认定同一文件矛盾。允许有充分来源依据的语义蕴含，例如“并”连接的通风和两项检测共同满足，而不是要求否定性QA照抄原句；仅与原文相容仍不足以获得支持。

模型最终23题pass、1题revise、26题hold，Codex另行完成逐题原文核对。hold包含未知/合并证据ID，以及provider标pass却仍有uncertain或unsupported_claims；解析器保存原始意见并保守标hold，不静默恢复为pass。正文完整但Markdown围栏未结束可去外壳解析，截断JSON仍拒绝。错误题号不自动改名；本批保留失败轮并重审相同候选。新增六项完整性测试，当前合计31项。

新增81个完整来源单元覆盖记录，累计149个；已经核对过的一个第三分册注记不重复计数。变压器试送表述、公共开关/GIS规则同时触发及故障设备检修复役仍列在未闭合问题中，未用高模型通过数或完整题数量掩盖这些缺口。

生成实现：[quality_pilot.py](../../qa_pipeline/quality_pilot.py)读取预先整理的[事实与问题规划](../../data/qa/batches/20261008/batch01/seed.json)，构建可追溯的答案片段和关联原文。它仍是小批量、来源约束下的设计，不声称已复现GraphGen或训练了专用生成器。[review_quality.py](../../qa_pipeline/review_quality.py)使用已配置的GLM进行事实核验、答案盲复答及逐题审阅，保存真实调用证据；脚本不自动给训练资格。

[verify_quality.py](../../qa_pipeline/verify_quality.py)核对冻结输入、真实响应及逐题来源核对记录的摘要，候选变更、缺审核或关键检查未确定时拒绝标记复核完成。它验证记录与内容一致，不替代语义判断。[测试](../../tests/test_qa_quality.py)覆盖遗漏恢复、逆序、完整链路缺项、重复内容和过期审核等拒绝路径。

参考方法及其范围见[研究综述](research.md)：覆盖规划借鉴GraphGen和LAB；答案盲复答借鉴Roundtrip Consistency；扩展上下文有效性借鉴pdfQA。此次流程增加显式条件、角色、禁止项和恢复要求复核，并记录其实际实现边界。

## 第五批：直流事故链路与跨册边界

第五批新增 53 题、7 个业务单元，累计 180 题、27 个业务单元。生成先从独立来源单元规划事实，再冻结候选，执行事实核验、答案盲复答和语义审阅；v3 对模型指出的越界表述完成来源收紧。没有导出训练数据。

本批把“现象—核查—权限—分支—恢复范围”作为链路边界：主控站过负荷立即控功率与方式申请分开；回线转换的两端检查和共用接地极电流不能省略；滤波器备用可用条件与10分钟限制、功率升降期间手动禁令和调度申请共同生效；线路再启动次数、许可、整流站操作、带电作业退出和测距对站核对分别保留。

第五分册降压建议与第三分册无降压方式的适用关系未闭合，OLT试验及检修后复役流程也未从片段推断。模型审阅统计为48 pass、3 revise、2 hold，事实核验为88 supported、2 ambiguous；这是文档忠实性复核记录，不是业务专家正确率。
