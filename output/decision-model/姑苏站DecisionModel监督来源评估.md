# 姑苏站 Decision Model 监督来源评估

评估日期：2026-10-09。范围仅限 `rawdoc/姑苏站`。

**适合开展原型，但应把“规程形成判定依据”和“案例/日志形成现场样本”结合起来。首选规程五、规程三、保护判据、跳闸表、厂家异常处理表，以及有明确结论的故障案例。日志、定值和图册各有作用，不能直接当成带正确答案的训练集。**

本次完成文件清点、原生文本/表格提取、结构扫描和正文抽读，并对重点PDF的判据、波形说明、异常处理表和新旧定值进行了页面核对。不是逐页人工精读或逐条业务标签审核；“适合”指监督来源有价值，不代表条款已经完成训练样本验收。

完整结果见 [逐文件清单](姑苏站逐文件监督来源清单.md) 和 [机器可读清单](姑苏站监督来源清单.json)。清单中每份文档有用途、纳入条件、原文定位/抽读摘录、提取限制及同内容副本路径。

姑苏目录中含建昌站参数、建昌专属日报及带“虞城/常熟/布拖”等称谓的历史联调资料。前者仅作对站背景，后者先核对工程名称映射、试验环境和软件版本，不能因存放目录就自动变成姑苏站本地规则。本评估未纳入 `rawdoc` 中其他站点目录。

## 2. 哪些最适合

| 来源 | 适合监督什么判断 | 优先程度与边界 |
| --- | --- | --- |
| **规程五：设备异常与事故处理**（D174） | 该查什么、属于哪个处置分支、是否满足处置条件 | **首选**。现象—检查—条件—处置较完整；保留许可、限制和交叉引用 |
| **规程三：运行方式及设备运行规定**（D172） | 当前方式是否允许、是否缺少前提、是否违反联锁/操作顺序 | **首选配套**。补足事故处理条款依赖的运行约束 |

| **线路保护判据＋直流保护跳闸表**（D020、D017） | 主辅判据是否满足、是否应动作、应有哪些出口 | **优先**。适合范围明确、可程序核对的决策任务；不能省略时间窗和投退条件 |

## 3. 从原文看到的具体决策结构

### 3.1 规程五可以产生有条件分支的判断

[规程五](<../../rawdoc/姑苏站/运行规程/规程五：±800kV姑苏换流站运行规程（设备异常与事故处理）.pdf>) PDF第36页、印刷第26页，6.1节“交流滤波器断路器SF6压力低处理预案”，并非只写“压力低则检修”。条款区分现场压力正常、压力高于闭锁值且不再下降、缓慢下降且未闭锁，以及迅速下降或已闭锁等情况；后续还有备用滤波器能力、功率调整、调度申请与操作顺序要求。

因此可监督“还缺少哪项检查”“属于哪个处理分支”“当前是否具备该步骤的前提”。只给一条压力低报警，就直接标上完整处置或确诊漏气，会丢掉原文条件。

### 3.2 跳闸表适合多个输出同时成立的判断

[直流保护跳闸表](<../../rawdoc/姑苏站/保护故障相关/RD2T0077200-0004,直流保护跳闸表.xls>) 的 `换流变压器区!A1:W4`，将保护名称、信号、出口动作分列。例如第3行 `ACBTDP_INST_TR` 同时在换流器层Y闭锁、跳闸启动失灵、锁定换流变开关、长期动作和触发录波等列打“×”。

它适合拆成逐项“该出口是否应动作”，或多标签任务。不能强制只选一个动作，也不能在未核实表格约定前把所有空白直接写成否定标签。不同表中同样的“×”含义可能不同：PCS-974FG-D手册里的“×”表示指示灯“无影响”。

### 3.3 厂家异常处理表适合训练“下一步查什么”

[PCS-9586A手册](<../../rawdoc/姑苏站/产品说明书/PCS-9586A阀控制单元说明书.pdf>) PDF第30页的A/B路电源故障，列出屏柜电源、空开及NR2304板卡等可能原因；先将故障系统切为非值班，再检查屏柜电源和端子输入，端子电压正常时才指向板卡故障。

这里正确的监督单位是带前提的排查分支。单凭“A/B路电源故障”就标“板卡故障”，会把可能原因误训成确定结论。

### 3.4 已找到可进一步对齐的“报告—日志”组合

| 候选组合 | 已核对的事实 | 仍缺什么 |
| --- | --- | --- |
| D016：2025年9月14日极1线路保护动作分析报告；D102：`事件第二阶段/saveevent2.txt` | 报告事件发生在2025-09-14 18:45；日志相同时段有345条事件。报告PDF第3页及波形解释了低电压辅助判据在主判据满足前复归，因而保护不动作 | 逐信号/设备对齐及关键波形状态提取。日志同刻出现事件，不等于包含内部判据完整时间轨迹；“疑似雷击”仍是疑似 |
| D019：案例汇编正文块470；D071：`saveevent0530.txt` | 案例记载2022-05-30 01:02解锁后电流下降和NORM_DIR_REQ异常；日志同分钟也有345条事件及功率方向请求 | 内部信号与OWS映射、完整工况和事件边界；D153同日日报只能先作辅助候选 |

第一组尤其适合验证“输入证据—判断—依据”的样本构建流程，但一个事件不能因拆出几百行日志就算几百个独立故障案例。这两组都尚未形成经过审核的训练标签。

## 4. 入样前必须处理的实际问题

1. **未闭合案例不能生成确定根因。** 案例汇编正文块518的2023-07-15 CCP121B退出运行事件，仍写着厂家继续研究并确认整改方案。缺陷表 `Sheet1!C4:D5` 也包含“反馈经研院和厂家”等状态。可以监督“证据不足/待查”，不能补写已确认原因。
2. **历史缺陷与现行规则要分开。** 案例汇编正文块478将CTRL LAN相关跳闸延时从2ms改为10ms；正文块512将Y-STOP等待窗口从1.5s改为5.5s。旧程序现象不能泛化为所有版本的正常机制。
3. **新旧定值确实不同。** D052旧DC22-0031与D050替代版DC22-0103，在各PDF第2页同一“I段动作定值(S2)”分别是50kV、55kV，已核对页面。替代关系不等于已确认今天的现场有效版本；也不能因新版难提取，就用旧版代替。
4. **日志名不一定代表事件日期。** `saveevent0607...` 部分文件正文为2022-06-08，`saveevent0613...` 部分为2022-06-14。以正文时间对齐日报，不以文件名对齐。
5. **不同文件可包含同一批事件。** D077的1,516条事件全部包含在D078的8,943条事件中（空白归一化后按多重集合核对），尽管原始顺序不完全一致。日报/周报还会复述同一试验。
6. **试验状态决定标签语义。** 主动断电、拔光纤或模拟故障后发生跳闸，可能是正确响应。应分别记录注入动作、预期响应、实际响应和额外异常；RTDS模型问题也不能标成现场硬件故障。
7. **站名、型号和表格结构影响结论。** 历史站名待映射；D003、D006的文件名与封面型号不同；缺陷表颜色编码验证状态，合并单元格承载试验名称。纯文本中都不能默默丢弃。

## 5. 建议首轮怎样使用这些资料

先选三个边界明确的小任务，而不是把所有文档批量改写成长问答：

| 试点任务 | 首批来源 | 判定目标 |
| --- | --- | --- |
| 装置报警分级与下一步检查 | PCS-974FG-D报警表、PCS-9586A异常处理、规程五对应章节 | 是否闭锁、是否需要处置、先检查什么、何时证据不足 |
| 线路保护判据与预期出口 | 线路保护判据、跳闸表、匹配版本定值；2025-09-14报告/日志用于案例核对 | 主辅判据和时间关系是否满足，保护/出口响应是否符合规则 |
| 运行/备用系统切换前提 | 直流二次典型操作票、规程三、相关调试记录 | 当前前提是否满足，下一步检查是什么，切换是否完成 |

每个样本保留 `state`（截止决策时刻可获得的状态）、`questions`（明确的判断问题）、`criteria`（适用判据）和 `gold`（审核后的标签），另附来源、站点、设备、模式、定值/软件版本、事件ID与证据位置。底层字段需按实际采用的Decision Model实现映射。

规程派生样本、真实事件样本、调试注入样本分别注明来源类型。规程可以生成满足/不满足条件的受控场景，但要验证物理与逻辑可行性；删除观测后的样本只有在确实无法判定时才能标“信息不足”。案例输入不得泄露事后分析结论。

按**原始事件、试验、规则条款及其改写族**划分训练/验证/测试，保证同一事件的日志、报告、日报及改写不跨集；如要检验新规则泛化，再留出整个规则族。对于依规判定类任务，用可执行规则/状态机作为基线；对于缺失观测、文本事件和多来源线索的判断，再评估Decision Model是否带来收益。准确率之外，应检查漏报、误报、信息不足时的表现和概率校准。

本次评估没有生成训练集或启动训练。当前资料最先能支持的是**可追溯的局部决策任务**；要监督完整的“从问题出发构建任务级语义模型”的过程，还需要额外记录概念发现、证据选择、模型更新、缺口识别及验证结果的过程轨迹。
