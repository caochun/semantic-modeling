# 姑苏站告警决策候选集 v1

**这是有证据条件的规则应用试点，不是真实故障训练集。** 目标是读取当前观测和给定的规则，判断本条信号是否闭锁，以及下一步应核查什么。

| 集合 | 规则族 | 原始模拟场景 | 两种表达记录数 | 决策标签数 |
| --- | ---: | ---: | ---: | ---: |
| train | 10 | 23 | 46 | 74 |
| calibration | 3 | 7 | 14 | 22 |
| test | 5 | 13 | 26 | 38 |
| 合计 | 18 | 43 | 86 | 134 |

训练入口只使用校准/测试集合的自然语言版本，实际校准为7场景、11个决策，测试为13场景、19个决策。结构化版本保留用于另行评估输入表达稳定性，不能当独立故障数。

## 来源与标注

- PCS-974FG-D非电量及辅助保护装置说明书，PDF第58–59页：自检报警、闭锁与处理意见。
- PCS-9586A阀控制单元说明书，PDF第29–30页：DSP报警的模式差异、电源排查、进程恢复、对时故障范围。
- 规程五设备异常与事故处理，PDF第36页/印刷第26页：SF6压力及弹簧储能相关核查。

适用范围仅是文件中指定的装置/条件。样本明确假设适用性已确认，或者将它作为缺失信息；没有把厂家手册自动认证为现场当前版本。手工设定场景与标签，经原文抽读、关键表格页面核对和程序检查，未做业务专家审核。

**`insufficient_evidence` 是一个明确类别，不是 `noul=0.5`。** 原文只有“可能”“基本判断”的地方不标唯一确定根因。不把“正常”事件等级解释成全系统健康，不虚构持续时间或定值。

## 文件与格式

| 文件 | 内容 |
| --- | --- |
| [review.md](review.md) | 43个场景的输入、候选项、候选标签和依据，供核读 |
| `train.jsonl` / `calibration.jsonl` / `test.jsonl` | Unsloth原生记录：`id`、`state`、`questions`、`gold` |
| `audit.jsonl` | 场景/规则族、来源页、哈希、标签理由、选项语义映射；不输入模型 |
| `rules.json` | 本批规则摘要、观察条件与场景定义 |
| `source_pages.json` | 原始来源版本与对应页面的提取文本；保留表格排版问题用于核对 |
| `manifest.json` | 数据文件SHA256及构建代码版本摘要 |
| `validation.json` | 数据完整性、分组、标签校验结果 |
| `upstream_validation.json` | 原版Unsloth数据函数与真实tokenizer的验证结果 |

`questions`、`gold`在JSONL中存为JSON字符串，避免Hugging Face Arrow合并动态问题/选项字典后插入null字段；官方 `_parsed` 原生支持这种形式。`state`保持文本或JSON字符串。展开后结构示意如下（省略的文字不是训练样本）：

```json
{
  "id": "example",
  "state": "适用规则……当前观测……",
  "questions": {
    "blocking": {
      "type": "choice",
      "instructions": "只判断本条信号是否闭锁装置；适用性未知时不得套用。",
      "criteria": {
        "blocks_device": "闭锁装置",
        "does_not_block": "该项不闭锁装置",
        "insufficient_evidence": "必要信息不足"
      }
    }
  },
  "gold": {"blocking": {"label": "insufficient_evidence"}}
}
```

下一步核查问题用 `c0`–`c3` 不透明键。每条记录重新分配键与选项含义，标签同步映射，避免固定位置或“follow_guidance”等键泄露答案。Clef会排序键，所以仅打乱字典插入顺序无效。

## 评估解释

同一规则族的全部场景和表达保留在同一集合；本批不同集合仍可能来自同一文档，不能宣称文档或站点独立。输入包含供判定的规则，测试测的是未训练规则族的**依证据应用**，不能当成闭卷知识记忆。规则本身包含条件—结论关系是有意的；事后根因、候选标签、核读理由和分组元数据均不放入模型输入。

部分候选选项较容易排除，未知型号场景也有明确提示；因此这是一批数据格式与训练流程的种子集，不能代表真实监盘难度。后续需要增加自然日志窗口、多个竞争规则、难负例、信号缺失/冲突，以及经核对的真实事件。

复现入口见 [实验说明](../../../experiments/decision_model/README.md)，双机GPU实测与概率校准的局限见 [试点记录](../../../docs/training/decision-model-gpu-pilot-20261009.md)。
